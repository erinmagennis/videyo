# Videyo hackathon architecture

## Request flow

```text
Browser
  |
  | POST /api/pipeline { prompt, mode }
  v
Vercel Python function
  |
  +--> demonstration mode
  |      deterministic SVG
  |      Genblaze RunBuilder + Manifest verification
  |
  +--> live mode
         Genblaze Pipeline
         OpenAI image provider
         ObjectStorageSink
              |
              v
         Backblaze B2
         asset + canonical provenance manifest
```

## Why B2 matters

B2 is part of the production path rather than a backup afterthought. Genblaze's storage sink moves the generated bytes into B2, rewrites the asset URL, calculates the asset hash, and stores the canonical manifest beside the output. The browser receives the durable asset location and verification data from the completed run.

## Why Genblaze matters

Genblaze owns the live provider call, run identity, step metadata, asset record, storage handoff, manifest creation, and integrity verification. The endpoint does not call OpenAI or B2 directly.

## Safety boundary

Live generation requires five server-side credentials plus `VIDEYO_LIVE_GENERATION=true`. Requests are limited to one image and 600 prompt characters. Errors return a public-safe message without credential or provider details. Demonstration mode is always labeled and makes no external model call.
